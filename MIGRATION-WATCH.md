# Architecture switch watchlist

Zero-build (vanilla JS) is the decided architecture (SPEC §8). When it runs out of road is decided by the indicators in SPEC §8.1: **any two tripped = feature work pauses and the A→B (Preact + Vite) migration happens first**; only one tripped = record the observation, leave the architecture alone.

Measure at the end of every development session and write anything over threshold into the log below.

| # | Indicator | Threshold |
|---|---|---|
| 1 | Lines in a single file | > 800 |
| 2 | Total app lines (excluding vendor) | > 2500 |
| 3 | Hand-written DOM update sites on one page (innerHTML / appendChild / attribute sync, **all three categories combined**) | > 25 |
| 4 | Independent state that has to sync across pages | > 6 |
| 5 | Repeat "the view didn't keep up with the data" bugs | fixed ≥ 3 times |
| 6 | Files touched to add one small feature | ≥ 4 **and total source files > 8** |
| ~~7~~ | ~~First paint~~ | **Deleted**: a zero-dependency static page can't reach this line, and a framework wouldn't cure it anyway |
| 8 | Async race guards (hand-written "discard stale response / cancel" sites) | > 3 sites |
| 9 | Optimistic-update rollback paths | > 2 |

## Memo

- **2026-07-28 process retro**: the ledger went 7 commits with nobody updating it, and #1 was tripped that entire time. The lesson isn't "we forgot" — it's that **booking had no trigger**. Feature commits and measurement commits were separate, held together by nothing but good intentions. The hedge: after the subcomponent split, `wc -l src/ui.js` goes into the pre-push hook's output (non-blocking, print only), so every push is forced to see the number.

- Indicators 8 and 9 were added after the dual-track review: all seven original indicators measure **static complexity** (line counts, update sites, state counts), while what actually forces you onto a framework is **concurrent writes**. openPR's race already consumed site #1 as of that day.
- The hedge worth doing whether or not you migrate: a single state object + an explicit `render()` + generation-counter guards (about 50 lines). The genuinely expensive part of a migration is prying state out of event closures, and that bill comes due either way.
- **2026-10-28 vendored mermaid (#188 M1)**: `vendor/mermaid.min.js` = mermaid **11.17.2** (pinned), 3,572,661 bytes, sha256 `581ed7d74bd9048d0e3a91363927d72ef22942d7722546b27f7cc29e35390eb8`, source https://cdn.jsdelivr.net/npm/mermaid@11.17.2/dist/mermaid.min.js. Loaded only by `sandbox.html`; the main page never loads it. The SW shell cache stores it (one extra ~3.5 MB on first open on a phone). Excluded from app line counts like other vendor files.
- The gate was expected to trip at **M3** (comment threads + post-submit refresh + optimistic marking) on indicators 3/5/9 — that wouldn't be a failure, it's precisely how §8.1 is designed to be used.
